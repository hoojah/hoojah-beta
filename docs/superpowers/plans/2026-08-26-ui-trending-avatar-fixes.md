## Task 1 — Fix production avatar upload: add `aws-sdk-s3`, commit storage config

production and every avatar upload fails. Both config files are already correct in the working

   already correctly shaped. Just include them in the commit.

## Task 2 — Profile header: show uploaded photo when attached, else initials tile

**Rationale.** `app/views/users/_profile_header.html.erb:91` renders
`render "ui/avatar", user: user, size: :lg, variant: :tile`, and in
`app/views/ui/_avatar.html.erb:42-44` the `:tile` variant unconditionally nils the URL
(`avatar_url = tile ? nil : ds_avatar_url(user)`), so an uploaded avatar never shows on the
public profile. Decision: `:tile` should show the uploaded photo **when actually attached**,
else the branded initials tile.

**Files.**
- `app/views/ui/_avatar.html.erb` — edit
- one new view spec (below)

**Change.** In `_avatar.html.erb`, replace the URL resolution (currently
`avatar_url = tile ? nil : ds_avatar_url(user)`) with:

```erb
<% avatar_url = (tile && !user.avatar.attached?) ? nil : ds_avatar_url(user) %>
```

Semantics, exhaustively:
- `variant: :tile` + `user.avatar.attached?` → `ds_avatar_url(user)` → `user.avatar.url` → photo renders.
- `variant: :tile` + not attached → `nil` → initials tile, exactly as today. This is the fallback
  every other `:tile` call site keeps.
- non-tile variants → unchanged (`ds_avatar_url(user)` as before).

**Critical constraint:** the attached check is `user.avatar.attached?` and nothing else. The
legacy `photo` string is a seeded random value present on **every** user — keying on `photo`
presence would show wrong images. (`ds_avatar_url` already prefers `avatar.url` when attached,
`app/helpers/design_system_helper.rb:263-266`, so no helper change is needed.)

While in the file, confirm the image branch of the partial applies the same `size: :lg`
dimension classes as the initials branch (it should already — the branches share the size
mapping). If it doesn't, make the image branch use the same size classes; do not restyle
anything else.

**Acceptance criteria.**
- Public profile header renders an `<img>` when the user has an attached avatar.
- Public profile header renders the initials tile when no avatar is attached, even though
  `user.photo` is present.
- All other `ui/avatar` call sites (non-tile variants, and tile call sites for avatar-less
  users) render exactly as before.

**Specs.** Add `spec/views/ui/_avatar_spec.rb` (view spec, `render partial: "ui/avatar"`),
three examples:
1. `variant: :tile`, avatar attached (`user.avatar.attach(io: StringIO.new("png"), filename:
   "a.png", content_type: "image/png")`) → rendered output contains `<img`.
2. `variant: :tile`, no avatar attached but `photo` present → output has **no** `<img`, and
   contains the user's initials (`ds_initials`).
3. no variant, no avatar → unchanged legacy behaviour (`<img` from `photo`), pinning the
   non-tile path.

Run: `RAILS_ENV=test RUBYOPT='-W0' bundle exec rspec spec/views/ui/_avatar_spec.rb` plus any
existing profile-page specs (`grep -rl "profile" spec/requests spec/system` and run the hits).

## Task 3 — Trending links: break out of the Turbo frame (`target: "_top"`)

**Rationale.** Trending links live inside `turbo_frame_tag "trending"`; clicking one asks Turbo
for a matching `trending` frame on the hujah show page, which has none → "Content missing".
Chosen approach (confirmed): put `target: "_top"` on **both frame declarations** so every link
inside — compact partial and rich partial alike — performs a full-page visit. Two edits, zero
per-link churn, and future links added inside the frame are covered automatically. Do **not**
add `data-turbo-frame` to individual links.

**Files.**
- `app/views/hujahs/index.html.erb` — line 46
- `app/views/trending/index.html.erb` — line 14
- one new system spec (below)

**Change.**
- `hujahs/index.html.erb:46`:
  `turbo_frame_tag "trending", src: trending_path, loading: :lazy`
  → `turbo_frame_tag "trending", src: trending_path, loading: :lazy, target: "_top"`
- `trending/index.html.erb:14`:
  `turbo_frame_tag "trending" do`
  → `turbo_frame_tag "trending", target: "_top" do`

No changes to `_trending.html.erb` / `_trending_rich.html.erb` links.

**Acceptance criteria.**
- From the feed sidebar, clicking a trending hujah navigates to that hujah's show page
  (URL is `/…slug…`, full page, no "Content missing").
- Same from the rich trending page (`trending/index`), both title (line 25/37 links).
- The lazy `src:` load of the sidebar frame still works (frame content appears on the feed).

**Specs.** New system spec `spec/system/trending_navigation_spec.rb` (`js: true`): create a few
hujahs with votes so `Hujah.trending` returns them (test cache is a null store, so no cache
busting needed), sign in, visit the feed, wait for the trending frame to populate, click the
first trending link, assert `page` has the hujah body and `current_path` is the hujah's path,
and `expect(page).not_to have_text("Content missing")`.
Run it plus existing trending specs: `grep -rl trending spec | xargs …rspec`.

**Rationale.** Current voted state is a heavy solid fill (`bg-#{stance} text-white`). Decision:
all three buttons are uniform **outlined** pills; the viewer's voted stance gets a subtle

**Files.**
- `app/views/hujahs/_vote_bars.html.erb` — button loop, lines 72-85
- `app/assets/tailwind/application.css` — one new safelist line (see checklist)
- optionally one existing compiled-CSS spec file (below)

**Change.** In the loop, keep the `button_to` form structure, `form:` options, `stance_icon`
glyph, and `voted = current_user_vote == stance` exactly as they are. Replace only the class
string (currently lines 78-80:
`"flex-1 h-11 rounded-xl border-[1.5px] border-#{stance} #{voted ? "bg-#{stance} text-white" : "bg-card text-#{stance}"} flex items-center justify-center gap-1.5 text-xs font-bold transition active:scale-95"`)
with:

```erb
"flex-1 h-10 rounded-full border-[1.5px] border-#{stance} text-#{stance} #{voted ? "bg-#{stance}-soft ring-2 ring-#{stance}" : "bg-card"} flex items-center justify-center gap-1.5 text-xs font-bold transition active:scale-95"
```

and, inside the button label, prepend a check glyph only when voted, before the existing
`stance_icon(stance)` + label content:

```erb
<%= lucide_icon("check", class: "w-3.5 h-3.5") if voted %>
```

(Match the lucide helper invocation style already used in this partial for `stance_icon` — if
the codebase calls it differently, e.g. `lucide_icon "check"`, follow the local style; the icon
name is `check`.)

Summary of the visual contract:
- **Unvoted:** `bg-card text-#{stance} border-#{stance}` outlined pill, `rounded-full`, `h-10`, `flex-1`.
- **Voted:** identical outline + `bg-#{stance}-soft` tint + `ring-2 ring-#{stance}` emphasis + leading check.
- **Never** `bg-#{stance} text-white` — the solid fill is removed entirely.
- `active:scale-95`, `transition`, `gap-1.5`, `text-xs font-bold` retained.

**Tailwind safelist — per class, explicitly:**
- `border-#{stance}` → already safelisted (`application.css:101`). No action.
- `text-#{stance}` → already safelisted (line 101). No action.
- `bg-#{stance}-soft` → already safelisted (line 102, `-soft` variants). No action.
- `ring-#{stance}` → **NOT safelisted; `-soft`/line-101 entries do not cover `ring-`.** Add,

- `rounded-full`, `h-10`, `ring-2`, `w-3.5`, `h-3.5`, `bg-card` → appear as **literal text in
  the ERB file**, which Tailwind v4 scans, so they compile without safelisting. No action.

**Acceptance criteria.**
- Three uniform outlined pills; no solid stance fill anywhere in the partial.
- Voted stance shows tint + ring + check; toggling vote moves the marker.
- `TailwindBuild.emitted?` is true for `ring-agree`, `ring-neutral`, `ring-disagree` after a

**Specs.** Locate the existing voting system spec (`grep -rl -i vote spec/system`) and run it —

## Task 6 — Sidebar trending: accent heading + card rows

**Rationale.** The compact sidebar trending list (`app/views/trending/_trending.html.erb`) is
all-grey; decision is to colour the heading/flame and promote each row to a small card, matching
the hand-rolled `bg-card shadow` cards on the rich page.

**Files.**
- `app/views/trending/_trending.html.erb` — heading (lines 17-19) and list (lines 22-31)

**Change 1 — heading.** Accent: `text-neutral` (the Spectrum orange the navbar flame already
uses — consistent flame = consistent colour; already safelisted at `application.css:101`).
Replace `text-grey` on the heading and flame icon with `text-neutral`. Keep the uppercase
treatment and sizing as-is.

**Change 2 — card rows.** Wrap each row's link in the card primitive. Mandatory form —
`render layout:`, never `render partial:` (partial-form silently renders nil):

```erb
<ul class="space-y-2 list-none p-0 m-0">
  <% trending_hujahs.each do |hujah| %>
    <li>
      <%= render layout: "ui/card", locals: {as: "article", padded: false, class: "rounded-xl"} do %>
        <%= link_to hujah_path(hujah.slug), class: "block p-3 text-sm text-grey no-underline hover:text-primary" do %>
          <%# keep the existing truncated body + @username span exactly as they are today %>
        <% end %>
      <% end %>
    </li>
  <% end %>
</ul>
```

Rules baked into that snippet:
- `padded: false` + padding carried by the inner link (`p-3`) — **never** combine `padded:` true
  with padding in `class:`, and never put padding utilities in the card's `class:` alongside
  `padded:`. If `ui/_card` has no `padded:` local (check its `local_assigns`), omit it and keep
  `p-3` on the link, ensuring the card itself adds no padding.
- `class: "rounded-xl"` — `ui/_card` bakes no radius (`ds_card_classes` → `CARD_BASE = "shadow
  bg-card"`); the caller opts in, and `rounded-xl` matches the current design language
  (navbar pills, vote buttons pre-change were `rounded-xl`).
- Keep the existing inner content (truncated body, `@username` sub-line with its
  `block text-xs text-grey/70 mt-0.5` classes) untouched; only the wrapper changes.
- Keep it compact: `p-3`, `space-y-2`, no headers/footers inside the card.
- The existing per-link classes move onto the new `link_to` block form as shown (still
  `block`, `text-sm`, `no-underline`, `hover:text-primary`).

All new classes (`space-y-2`, `p-3`, `rounded-xl`, `list-none`, `p-0`, `m-0`) are literal in
ERB — no safelist entries needed. `_trending_rich.html.erb` is not touched.

**Acceptance criteria.**
- Sidebar heading + flame render in the neutral orange accent.
- Each trending row is a discrete white `shadow bg-card` rounded card with comfortable compact
  padding; whole card surface is the link target; hover still shifts text to primary.
- Rich trending page (`/trending`) unchanged.
- Task 3's `target: "_top"` behaviour still holds (links are still inside the same frame).

**Specs.** Re-run Task 3's `spec/system/trending_navigation_spec.rb` (proves the restructured
markup still lazy-loads and navigates) plus any view/request spec touching `trending`
(`grep -rl trending spec`).
