# Rails 6.0 → 8.1 Upgrade + Backend Modernization — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take Hoojah from Rails 6.0.3 / Ruby 2.7 / Webpacker 4 to Rails 8.1 / Ruby 3.4.9 with modern backend defaults, keeping the React SPA working and a green test suite at every hop.

**Architecture:** Characterize-then-hop. Build a request-spec safety net on a booting 6.0 baseline, then climb the 7 official Rails hops one at a time (detect → bump → apply → verify → commit), migrating Webpacker→shakapacker mid-climb so React keeps building, then a final modernization sweep on 8.1.

**Tech Stack:** Ruby (2.7.8→3.4.9), Rails (6.0→8.1), RSpec + FactoryBot, shakapacker, jsonapi-serializer, Solid Queue/Cache/Cable, Propshaft, Kamal. Tooling: `rails-upgrade-assistant`, `rails-security-auditor`, `rails-simplifier` (maquina plugins).

**Orchestration (per hop):** Opus (main) runs the detection script → **Fable subagent (effort ≤ high)** turns findings + the assistant's version guide into that hop's migration plan → **Opus executor subagent(s)** apply it → **fresh Opus verifier subagent** checks the diff against the plan before commit.

**Reference:** Spec at `docs/superpowers/specs/2026-08-03-rails-6-to-8.1-upgrade-design.md`. Version guides at `~/.claude/plugins/marketplaces/maquina/rails-upgrade-assistant/version-guides/`.

---

## Conventions used in this plan

- **Test command** (until noted otherwise): `bundle exec rspec`.
- **Boot smoke check:** `bin/rails runner 'puts "BOOT OK: Rails #{Rails.version} / Ruby #{RUBY_VERSION}"'`.
- **Never commit red.** Each task's final step is green tests + commit.
- **Commit style:** no Claude/Anthropic trailer (workspace rule).
- **Characterization ≠ fixing.** Phase 0 specs capture *current* behavior, bugs included. If a hop legitimately changes behavior, update the spec in that hop's commit with a note.

## Phases 1–7 — The version hops

> Each hop follows the **identical procedure** below. Do them strictly in order:
> **6.0→6.1 (P1), 6.1→7.0 (P2), 7.0→7.1 (P3), 7.1→7.2 (P4), 7.2→8.0 (P5), 8.0→8.1 (P6).**
> (Six hop-transitions across seven versions.)

### Per-hop procedure (apply for each hop below)

**Files (per hop):**
- Modify: `Gemfile`, `Gemfile.lock`, `.ruby-version` (when the hop bumps Ruby)
- Modify: `config/application.rb` (`config.load_defaults`), plus whatever `rails app:update` touches
- Create: `config/initializers/new_framework_defaults_<version>.rb` (from `app:update`)
- Create (scratch, not committed): `rails_<version>_upgrade_findings.txt`

- [ ] **Step 1: Generate & run the detection script** — Opus (main). Use `rails-upgrade-assistant` to generate the version-specific detection script for this hop; run it; produce `rails_<version>_upgrade_findings.txt`. Read the matching `version-guides/upgrade-<from>-to-<to>.md`.

- [ ] **Step 2: Architect the hop** — dispatch a **Fable subagent (effort ≤ high)** with the findings file + the version guide. It returns an ordered migration plan for *this app's* findings (which gems, which config, which code sites). No boilerplate/research is sent to Fable.

- [ ] **Step 3: Bump the Gemfile (and Ruby if the hop requires it)** — set the Rails constraint to the hop's target (see each hop below), apply the Ruby bump if listed, then:

```bash
mise install ruby@<version>   # only on hops that bump Ruby
mise use ruby@<version>       # only on hops that bump Ruby; update .ruby-version
bundle update rails
```

- [ ] **Step 4: Run `rails app:update`** and reconcile the diff — accept new files (keep the generated `new_framework_defaults_<version>.rb`), and manually merge changes into existing config rather than clobbering app-specific settings.

- [ ] **Step 5: Apply the Fable plan's code fixes** — dispatch **Opus executor subagent(s)** to apply the findings fixes (parallel where independent). Update any characterization spec whose *expected* behavior legitimately changed this hop, with a note in the commit.

- [ ] **Step 6: Flip framework defaults** — set `config.load_defaults <hop version>` in `config/application.rb` and delete the corresponding `new_framework_defaults_<version>.rb` once its settings are confirmed default-safe.

- [ ] **Step 7: Green + boot gate**

Run: `bundle exec rspec`
Expected: PASS, example count ≥ baseline count.
Run: `bin/rails runner 'puts "BOOT OK: Rails #{Rails.version} / Ruby #{RUBY_VERSION}"'`
Expected: prints the hop's Rails + Ruby versions.

- [ ] **Step 8: Fresh-eyes verification** — dispatch a **fresh Opus verifier subagent**: given the hop's Fable plan + the git diff, confirm every planned item landed, no unrelated changes, tests actually green. Fix anything it flags.

- [ ] **Step 9: Log & commit**

Append a row to `docs/superpowers/UPGRADE-LOG.md`, then:

```bash
git add -A
git rm -f --ignore-unmatch rails_*_upgrade_findings.txt
git commit -m "Hop: Rails <from> -> <to> (green, boots)"
```
