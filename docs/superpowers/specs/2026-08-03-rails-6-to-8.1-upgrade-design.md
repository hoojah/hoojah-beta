# Project 1 — Rails 6.0 → 8.1 Upgrade + Backend Modernization

**Status:** Approved (design) — 2026-08-03
**App:** Hoojah (`hoojah-beta`)
**Author:** Rudzainy Rahman (with Claude Code)
**Strategy:** Characterize, then hop (sequential, no version skipping)

---

## 1. Context

Hoojah is a small Rails **6.0.3** application (Ruby 2.7 target) that acts as the JSON
API backend for a **React 16 single-page app**:

- **Models (5):** `user`, `hujah`, `vote`, `flag`, `notification`.
- **Auth:** session-based, `bcrypt` (`sessions_controller`, `/login`, `/logout`, `/logged_in`).
- **API:** `Api::V1::*` controllers (hujahs, votes, flags, notifications, users) serialized
  with **`fast_jsonapi`**.
- **Front-end:** React 16 SPA (react-router-dom, react-query, react-bootstrap, axios,
  ~40 components) mounted through **Webpacker 4** into a single catch-all view
  (`get '/*path' => 'hujah#index'`).

### Constraints discovered
1. **Almost no safety net** — only 3 real spec files run (`notification`, `flag`,
   `hujah_serializer`); `spec/models/hujah.rb` is misnamed and never runs.
2. **The old stack cannot boot on this machine** — only Ruby **3.4.9** (mise) is installed;
   `.ruby-version` pins 2.7.0 (not installed); Rails 6.0 will not run on Ruby 3.4.
3. **Housekeeping** — a stray junk file `=2.8.0` (a bad `yarn add` redirect) sits in the repo root.

### Decisions locked (brainstorming)
- **Strategy:** Characterize, then hop.
- **Target:** Rails **8.1** (7 hops: 6.0→6.1→7.0→7.1→7.2→8.0→8.1).
- **Scope:** Full modern backend conventions.
- **Front-end:** React SPA is **kept alive** through the upgrade (migrated to shakapacker).
  Hotwire (Turbo+Stimulus) and Hotwire Native are **separate follow-on projects** (2 & 3).

### Decomposition
This overall request is three independent projects. This spec covers **Project 1 only**:

| # | Project | Depends on |
|---|---------|-----------|
| **1** | **Rails 6.0 → 8.1 upgrade + backend modernization** (this spec) | — |
| 2 | React SPA → Hotwire (Turbo + Stimulus); retire Webpacker/React → importmap + Propshaft | Project 1 |
| 3 | Hotwire Native (Rails-side path-config + native auth, then a separate native shell repo) | Project 2 |

## 2. Guiding principles

- **Green suite is the gate at every hop.** No hop commits red.
- **One hop at a time.** `rails-upgrade-assistant` is sequential by design; reconcile
  `rails app:update` config drift per hop, never batched.
- **Keep the app working.** The React SPA must keep building and booting through every hop
  (Webpacker 4 is dead on Rails 7+, so migrate to **shakapacker** early).
- **Fable does architecture, Opus does execution.** ~10% Fable (per-hop migration plan +
  ambiguous judgment), everything else Opus subagents.

---

## 3. Phase breakdown

### Phase 0 — Baseline & safety net
- **Housekeeping:** delete stray `=2.8.0`; rename `spec/models/hujah.rb` → `hujah_spec.rb`;
  sanity-check `.rspec`.
- **Ruby baseline:** install a 6.0-compatible Ruby via mise.
  - Target **2.7.8**.
  - **Fallback:** if 2.7 will not compile on macOS 25 / arm64, use **3.0.x** (Rails 6.0 runs
    on 3.0 with minor warnings). Decision + outcome recorded in the upgrade log.
- **Boot the baseline:** `bundle install`, create/prepare DB, get the existing 3 specs green
  → prove 6.0 boots.
- **Characterization specs (the net):** request specs for every `Api::V1::*` endpoint
  (hujahs, votes, flags, notifications, users), the session/bcrypt auth flow
  (`/login`, `/logout`, `/logged_in`), and serializer output. These guard all 7 hops.

**Exit criteria:** baseline boots on the chosen Ruby; full suite (existing + characterization) green; committed.

### Phases 1–7 — the hops
Sequence: `6.0→6.1→7.0→7.1→7.2→8.0→8.1`. Each hop has the identical shape:

1. **Detect** — `rails-upgrade-assistant` generates the version-specific detection script;
   run it; produce `rails_<version>_upgrade_findings.txt`.
2. **Bump** — update `Gemfile` (Rails + affected gems) and Ruby as required:
   2.7 → **3.1** by Rails 7.1, → **3.2** by 8.0, → **3.4.9** by the final hop.
3. **Apply** — fix findings; run `rails app:update`; reconcile the config diff and adopt the
   new framework defaults (`config.load_defaults <version>`).
4. **Verify + commit** — full suite green + boot smoke check → commit the hop.

**Shakapacker note:** migrate Webpacker → shakapacker during the **6.1 → 7.0** hop (where
Webpacker breaks), so React keeps building. No React source rewrite (that is Project 2).

**Per-hop exit criteria:** `config.load_defaults` at the hop version; suite green; app boots;
detection findings resolved or explicitly deferred with a note; committed with a one-line log entry.

### Phase 8 — Modernization sweep (on Rails 8.1)
- **Serializers:** `fast_jsonapi` → **`jsonapi-serializer`** (drop-in successor; update
  requires/usages; serializer specs stay green).
- **Framework infra:** adopt **Solid Queue**, **Solid Cache**, **Solid Cable**.
- **Config hygiene:** verify **Zeitwerk** autoloading; move secrets to encrypted
  **credentials**; **Propshaft** for server-side assets (React stays on shakapacker until Project 2).
- **Deploy:** **Kamal**-ready configuration (not a deploy, just ready).
- **Quality gates:** `rails-security-auditor` full audit; `rails-simplifier` pass on
  touched code.

**Exit criteria:** on 8.1 / Ruby 3.4.9; suite green; security audit reviewed; React SPA still
serves; upgrade log complete.

## 4. Orchestration model (Fable architect + delegate)

- **Opus 4.8 (main loop):** research, run detection scripts, coordinate, integrate, run tests.
- **Fable subagent = architect** (effort ≤ `high`): per hop, digests detection findings +
  version guide → returns the migration plan for that hop. No boilerplate/research sent to Fable.
- **Opus subagents = executors:** apply mechanical fixes, write characterization specs; run in
  parallel where independent (subagent-driven development).
- **Fresh Opus subagent = verifier:** after each hop, reviews the diff against the hop's plan
  with fresh eyes before commit.

Tooling per phase: `rails-upgrade-assistant` (detection + version guides, every hop),
`rails-security-auditor` (Phase 8), `rails-simplifier` (Phase 8 + touched code),
`better-stimulus` (reserved for Project 2).

---

## 5. Testing & verification

- **Gate:** green RSpec suite at every hop; no red commits.
- **Backbone:** Phase 0 characterization specs (API + auth + serializers).
- **Additions:** deprecation-driven specs as findings require.
- **Smoke:** `rails runner` / `rails s` boot check each hop.
- **Completion discipline:** `superpowers:verification-before-completion` before any "done"
  claim — evidence (command output) before assertions.

---

## 6. Risks & mitigations

| Risk | Mitigation |
|------|-----------|
| Ruby 2.7 won't compile on macOS 25 / arm64 | Fall back to Ruby 3.0.x baseline; document the choice |
| Webpacker 4 dead on Rails 7+ | Migrate to shakapacker during 6.1→7.0; keep React building |
| Thin original tests | Phase 0 characterization suite (the reason for this strategy) |
| `fast_jsonapi` unmaintained | Swap to `jsonapi-serializer` in Phase 8 |
| Multi-hop config drift | Reconcile `rails app:update` diff per hop, never batched |
| A hop's findings too large to finish cleanly | Defer non-blocking items with a logged note; never commit red |

---

## 7. Deliverables

- Rails **8.1** on Ruby **3.4.9**, full suite green, React SPA still working.
- Modern backend defaults: Solid Queue/Cache/Cable, encrypted credentials, Kamal-ready,
  `jsonapi-serializer`, Propshaft (server assets), Zeitwerk verified.
- A **characterization spec suite** that did not previously exist.
- Per-hop commits + a concise upgrade log.
- Clean handoff point for Project 2 (Hotwire).

### Out of scope (future cycles)
- Hotwire / Turbo / Stimulus front-end migration (Project 2).
- Hotwire Native (Project 3).
- Retiring React / removing shakapacker.
